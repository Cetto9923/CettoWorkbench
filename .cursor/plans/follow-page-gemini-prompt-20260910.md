## 一、业务需求 Tab（按产品口径改）

### 产品定义
关注页业需 = **「我点过星或被卷入（star ∪ mailto）的、默认只看未关闭」的工作清单**。
不是禅道「是否重点关注 `isNeedFocus`」浏览器，也不是关闭档案。

### 必做

1. **默认列表改为未关闭**
   - 进页默认 `scope` / 过滤语义 = **未关闭**（`status <> closed`），不要再默认 `all`（当前会把已关闭灌满列表）。
   - 顶部统计卡只统计**当前关注集合里未关闭**的生命周期桶：`梳理中 / 实施中 / 已发布`；「已关闭」可保留为第 4 卡或筛选项，但**不得作为默认列表**。
   - 点「已关闭」筛才展示关闭项。

2. **删除一级筛「重点关注」「未关闭+重点」**
   - 对应 `FollowScopeKey` / `FollowScopeKeyOpen`（`key` / `key_open`）从工具栏按钮移除。
   - 后端可保留字段兼容，但前端不再暴露；统计卡上的 Key/KeyOpen 数字不必再驱动筛选项。
   - `isNeedFocus` 若仍返回，最多做行内弱标签（小 tip），**不是筛选项**。

3. **主筛收敛为（建议）**
   - 全部未关闭（默认）
   - 梳理中（lifecycle=clarifying）
   - 实施中（lifecycle=implementing）
   - 已发布（lifecycle=released，可选）
   - 已关闭（显式点选）
   - 删掉「未关闭·正常推进 `open_clean`」一级按钮（与「全部未关闭」重叠且难解释）；若后端仍算 OpenClean，可不展示。

4. **行展示优先「为什么还要我管」**
   - 保持现有紧凑单行 + 星标取关（`FollowSetDemand` + `appFetch`，勿改回裸 fetch）。
   - 保留：对象#ID、标题、研发阶段、进度摘要、关键时间、排期、查看详情。
   - mailto 来源可弱标「抄送」；star 不额外标。

5. **自动关注（本轮只做「设计落地的最小集」，可分 commit）**
   - **本轮可先不做写入**，但在代码注释/README 片段写清下一期入口；若顺手实现，仅以下场景自动 `ajaxFollowObject`（失败不影响主流程）：
     - 我创建 / 我是 BRA·QD·RD / 我受理
     - 我完成评审（通过或驳回）
     - 我发起催办或提测
   - **明确不做**：按系统/项目全员关注、按 `isNeedFocus` 自动关注、关键词订阅。

### 验收（业需）
- [ ] 刷新 `/follow` 业需 Tab：默认列表**无已关闭**（或关闭数为 0）；顶部卡以未关闭为主。
- [ ] 工具栏**看不到**「重点关注」「未关闭+重点」。
- [ ] 「已关闭」可点开看到关闭项；星标取关/再关注仍成功（非 CSRF 失败）。
- [ ] 相关单测/编译通过。

## 二、项目周报 Tab（默认我参与，再我关注）

### 现状（务必先读再改）
- 前端 `web/static/js/po/follow.js` 请求 `/follow/project-weeklies` 时写死 `scope: "watched"`（仅 `zt_project.follow`）。
- 后端 `ProjectWeeklies` 仅支持 `scope=watched|all`（`internal/module/po/service_weekly.go` / `repo_weekly.go`）。
- 筛「状态关注」依赖 `OverallSituation in (1,2)`，线上常年 0，与「周报异常/偏离」重叠，**删除**。
- 周期下拉目前只有「最新周报」一个 option，属死控件，**删除**。
- 「本周投入」列大量 0 人/怪异工时，PO 关注周报闭环用处弱，**本轮删除该列**（后端字段可留）。

### 「我参与」定义（写死，勿自创）
项目满足任一即「参与」：
1. `zt_project.PM = 当前账号`
2. 当前账号在项目团队：`zt_team` 中 `root = projectID` 且 `type = 'project'`（与禅道项目团队一致；若本库 type 值不同，先 `EXPLAIN`/抽查再对齐，但语义必须是项目成员表）

「我关注」：现有 `p.follow LIKE '%,{userId},%'`。

### 必做

1. **列表默认范围 = 参与 ∪ 关注**
   - 新增 scope，例如 `mine`（或 `participated_or_watched`）：SQL 取并集，去重。
   - 前端关注页默认改用该 scope，**不要**再用单纯 `watched`，也**不要**默认 `all`（全库）。
   - 排序：**参与在前，关注在后**；同组内可按最新周报/异常优先（沿用现有合理排序即可）。
   - 行上徽章：`参与` / `关注`（若两者皆是，只显示「参与」或「参与·关注」，二选一写清并统一）。

2. **范围切换（可选但推荐，最多 3 个）**
   - 默认：我的（参与+关注）
   - 仅参与
   - 仅关注
   不要做「全部项目」入口（除非已有权限模型；本轮不做 `scope=all` 暴露到关注页）。

3. **删无用筛/字段**
   - 删除筛选项：「状态关注」（`attention`）及对应统计按钮。
   - 删除控件：`#pwPeriodSelect`（仅最新周报时）。
   - 删除表格列：「本周投入」。
   - 保留筛：全部 / 待提交 / 有问题·风险 / 有计划·上线偏离；顶部卡：项目数 / 本周已报 / 本周待报 / 周报异常（文案可将「监控项目」改为「我的项目」）。
   - 操作列保留：查看周报、历史、取消关注（**仅关注关系**可取消；纯「参与」无 follow 时隐藏取消关注或禁用并提示「参与项目不可在此取关」）。

4. **文案**
   - 页脚「共 N 个关注项目」→「共 N 个项目」或「参与+关注」。
   - Tab 角标与列表 total 同源。

### 验收（周报）
- [ ] 默认列表含「我是 PM 或项目成员」的项目，即使未点关注。
- [ ] 仅关注、未参与的项目仍出现，排在参与之后，带「关注」标。
- [ ] 无「状态关注」筛、无周期空下拉、无「本周投入」列。
- [ ] 取消关注仍只改 `zt_project.follow`（既有逻辑），不误伤团队成员身份。
- [ ] 编译重启 :8090，用 `<本地测试账号>` 打开 `/follow` 项目周报 Tab 自测。
