## 4. 冻结的业务边界

1. 待办代表当前责任事项；已办代表本人真实正式动作事件；通知代表接收的信息。已读不等于已处理，已办不由待办消失生成。
2. 不改变actor范围、产品成员政策、superadmin语义、权限码、路由鉴权、CSRF或通知接收人限制。
3. 不因首页总量与待办总量不同就强行修成相同。先核对范围；首页生命周期关联范围不自动等于个人待办。
4. 不改阻塞、挂起、超期、今日到期的业务定义。当前待办SQL把refuse作为blocked且前端标签称已挂起，记录为口径冲突，必须取得业务定义后另行修复。
5. 不从通知正文、标题中的数字或链接猜测objectID；没有权威关联只显示“关联信息缺失”。mail显示“邮件通知”，不是业务对象类型。
6. 不过滤掉历史通知、重复事件或未知对象以让UI好看。不擅自去重业务记录、不更改计数。
7. 未接入待办对象的默认处理：保留分类位置但明确“未接入”，不可显示为0个真实事项；对应无实现筛选禁止可选。不得自行补齐跨模块责任政策。
8. 已有能力继续可用，不把已办正式动作集合、时间区间、结果筛选删掉以简化页面。
9. 通知“全部标为已读”继续作用于当前用户全部通知，不变成当前页或当前筛选；旁边明确范围。
10. 不新增AI功能、模型接口、自动决策、自动执行入口。

## 7. 后端缺陷与业务门（不能混成一次美化）

### G1：待办对象覆盖

默认本轮不扩展QueryTodoUnified的数据源或责任政策。核对已有PRD/测试和其他Agent变更，若对象已经接入则按新证据保留；否则UI标“未接入”，不可用0计数欺骗用户。
真正接入story/testtask/issue/risk/todo/approval另列任务，必须先冻结actor范围、状态、优先级、截止日期、阶段、分类计数、排序、去重的业务定义；没有定义标WAIT DECISION。用户要求视觉优化不构成这些业务政策的批准。
“我关注”无实际来源时同样不得伪装正常0数据；标未接入，保持既有已实现关系可用。

### G2：通知文本与关联

允许在通知响应的显示文本转换处进行最小修复：使用项目已有或现成HTML解析能力提取纯文本；去掉script/style节点及内容，解码实体一次，归一空白；不能只正则剥标签留下CSS。只对输出副本转换，不回写zt_notify。
主副标题正规化后相同则不渲染副标题。摘要上限按字符/rune而非字节处理，正文不应全部塞进列表tooltip/DOM；必要详情另需真实已有入口。
只使用权威结构字段和现有action关联生成对象链接；缺失显示“关联信息缺失”，mail用“邮件通知”。解析旧邮件正文补对象ID、变更分类规则和修复历史数据均WAIT DECISION，不能混入显示修复。
测试含style/script、中文、实体、双重转义、空正文、重复摘要、恶意标签；不新增不必要的解析框架。

### G3：失败语义

首页Home失败：保持可用页面外壳，但返回明确页面错误字段或既有错误页；失败统计显示“暂不可用”，不得显示真实0。独立失败的窗口组件可显示局部错误，不把其伪装暂无窗口。先写handler/service测试固定行为。
已办标题查询错误应向上返回或显式部分加载失败；不存在的对象可以显示“原对象不可用”，不能把数据库故障当对象缺失。保持历史事件，不擅自过滤已删除对象。
Service actor空时现有返回空成功属于既有合同风险；本轮记录，不顺手改全局身份或路由逻辑。

### G4：首页SQL分页（有条件独立包）

这是确定性规范欠缺，但不是CSS前置。UI包可先完成；此包缺环境/范围证据不得标完成。
前置：明确允许本包后端实施，已有隔离MySQL安全配置及真实Schema证据，冻结当前阶段/范围/去重规则。禁止访问或写真实zentaopms测试，禁止猜DSN。
设计固定：Repo负责跨阶段结果的SQL去重、过滤、稳定排序、count及LIMIT/OFFSET；Service组装业务字段，不直接持有gorm.DB；Handler绑定分页并返回items/total/page/pageSize。旧调用方全部搜索确认，响应字段添加优先向后兼容。
按当前合法基线结果建立夹具，不新增“优先推荐”排序；不能以阶段循环的偶然顺序当业务优先级。若全局排序缺少有效定义，STOP本包并列WAIT DECISION，不静默改为优先级排序。
首页分页点击必须重新取当前页；移除“查看全部”全量加载入口，改为普通分页可遍历全部记录。统计是SQL全量聚合，不是当前页统计。
验证有界返回、重复阶段的kind+id去重、稳定排序、相邻页无重复/漏项、范围不扩大、零数据、不同pageSize、最后页、非法参数。记录SQL数/响应大小/延迟和夹具规模，未实测不能许诺性能倍数。
不得为了此包重新实施现有todos/notice SQL分页或修改已有P卡验收状态。
