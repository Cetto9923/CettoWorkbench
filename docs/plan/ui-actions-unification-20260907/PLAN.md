日期：2026-09-07。状态：PLAN；已做源码审查，未实施业务修复，未做本轮真实浏览器或 DB 验收。

## 目标（可直接交给 Cursor）

在 workbench-claude-po 当前安全分支上，按本 PLAN 持续修复全站优先级与同类公共 UI 不一致问题，并落实“标题进入工作台详情、ID 进入禅道原始详情、操作栏办理当前价值流事项”。统一 P1/P2/P3/P4 的含义、颜色、尺寸和深浅色表现，让操作由服务端依据真实阶段、对象类型、当前用户权限及前置条件派生。复用现有排期能力，选择性参考 CRCBWorkbench 的提测、验收、催办和交付实现。逐批修复、验证、记录，直到所有范围内页面和阶段通过验收；任何未实现入口、权限歧义或缺少运行证据的项目不得标记完成。

## 3. 公共 UI 规范与迁移范围

### 优先级

- 采用全站一致方案：P1 红、P2 橙、P3 蓝、P4 中性灰；文字始终保留 P1–P4，不能仅靠颜色辨认。
- 统一浅色语义背景、语义文字及细边框；建议标准高度 20px、字号 11px、字重 600、水平内边距 6px、圆角 4px。如真实密集表格需要紧凑尺寸，只提供共享尺寸变体，不增加页面私有样式。
- 使用共享 CSS 类（如 wb-priority 与 data-priority="1"）；组件不依赖 .table 祖先，在列表、看板、详情、抽屉、弹窗中一致。
- 颜色从全局语义 token 获取；必要的 priority token 在现有主题源集中定义。深浅色只调整 token，不复制页面选择器，不引入第二套主题状态。
- 数值规范化先核对 demand/story/task/issue 的真实来源及当前转换。原始值与展示等级分离，不修改数据库优先级含义；已有已验证解析优先复用。
- 未设置显示中性“—”；未知或无效值不得自动伪装成 P2/P3/P4。已确认的新建表单默认值与“读取缺失数据时补默认值”分开处理。
- SSR 和动态 DOM 使用同一 markup/CSS 合同；只有确有重复渲染时才增加小型共享 helper，不为标签创建框架。
- 迁移后删除被替代的旧优先级样式和本次产生的孤立代码，禁止通过末尾追加 !important 叠盖解决。

### 同类公共 UI

- 对象类型建议统一：业务需求蓝、业务子需求紫、研发需求青；统一完整语义及紧凑文案，不以红色表示普通研发对象。使用共享类型标签和主题 token。
- 价值流阶段、禅道原始状态、风险等级、优先级是不同维度，分别命名，禁止共用含义模糊的 p1/active 类来推导业务状态。
- 同类行操作统一按钮尺寸、hover/focus/disabled/loading；内部导航与外部链接区分，禁用原因可见且键盘可访问。
- 相同职责的分页、toast、modal、加载/空/错误/重试复用现有成熟组件；先验证合同，不盲目迁移或合并不同 fetch 返回协议。
- 全站盘点所有已注册页面及其模板/脚本/样式，覆盖 PO/SM/业务/PMO（以实际路由为准），含列表、详情、看板、抽屉、弹窗。不得仅修首页和待办就称全局完成；不含禅道站点和第三方页面。

## 4. 导航和操作矩阵

- 标题：真实工作台详情 URL，当前页打开，支持复制链接、返回与恢复筛选分页。业务需求和研发需求均适用；当前研发详情入口需核实并补齐，不将研发 ID 塞入业务需求详情。
- ID：对应对象的禅道原始详情，由现有 URL builder 生成。外部原文允许新页打开以保留办理上下文，带 noopener noreferrer。
- 操作：每行一个主要阶段动作；“全部”视图按每行真实阶段处理，不按当前筛选项统一派发。不得用查看详情作缺失动作的兜底。

| 阶段 | 操作 | 行为 |
|---|---|---|
| 受理 | 审批 | 进入真实审批流程；核对受理与审批是否同一业务操作，不能把旧受理接口简单改名 |
| 澄清 | 澄清 | 进入当前对象的澄清办理流程 |
| 排期：业务需求 | 排期 | /schedule/demands/:id/scheduling |
| 排期：独立研发需求 | 排期 | /schedule/stories/:id/scheduling |
| 提测 | 提测 | 提测办理页；区分业务聚合提测和独立研发提测，不复用错误对象 ID |
| 联调测试 | 测试单 ↗ | 打开真实关联禅道测试单；多张用选择列表，不猜“最新一张”；无数据为暂无测试单 |
| 验收：本人为实际验收人 | 验收 | 进入验收办理并执行服务端授权 |
| 验收：本人非验收人 | 催办验收 | 仍需真实催办权限；确认对象、接收人、内容后提交，不因非验收人就自动授权 |
| 发起交付 | 发起交付 | 校验交付责任与前置条件，接通真实办理流程 |
| 发布 | 留空 | 暂不实现跟进验证，不创建假按钮或成功提示 |
| 评价反馈 | 评价／查看评价 | 由当前用户待评价资格与真实评价记录判定；多人评价不能以“别人已评”阻断本人待评 |

无办理权限时显示准确的等待说明；阶段或前置条件变化时提示刷新。挂起、关闭、驳回按真实规则处理，不能只凭阶段字符串提供写操作。

### 实施前必须查明的业务契约

1. 审批到底对应需求受理、评审还是主管部门审批；具体审批人和状态流转。
2. 交付执行人、评价人、评价次数及业务/独立研发需求各自的数据来源。已有确定规则则复用，否则保持该项待确认，继续其余修复。
3. 评价反馈阶段建议同时容纳待评价和已评价；旧 CRCB 规则以“已有评价”决定进入该阶段，与“评价”入口冲突。此建议尚待业务确认，不能静默改统计口径。
4. 测试单对象关联与可见性：批量获取真实关联，禁止虚构 URL、跨对象套用 ID 或用缺失数据冒充无测试单。

## 5. 后端与参考实现

- Handler 处理协议；Service 统一派生 stageKey、workbenchUrl、zentaoUrl 和 primaryAction（key/label/kind/url/enabled/reason），字段命名服从实际代码惯例。前端只展示，不自行推导权限。
- 能否展示按钮和写接口使用相同业务授权规则；所有写请求重新读取必要的最新状态，校验 capability、对象权限、前置条件和并发冲突。
- Repo 批量查询本页需要的角色、测试单、评价等事实；不在行循环查 DB，不新增 N+1，不破坏 SQL 筛选/排序/count/分页。
- 浏览器写入使用 CSRF fetch、JSON、真实 HTTP 方法，防重复提交，保留真实错误。不要假定 appFetch 自动解析 JSON 或拒绝所有非 2xx。
- 成功后刷新列表、阶段计数及受影响汇总，保留上下文；处理读写分离延迟，不能用前端假数据冒充已保存。
- CRCBWorkbench 参考位置：internal/module/workbench/action_rules.go、handler_submittest.go、handler_acceptance_delivery.go 及其实际 Service/Repo/页面/测试链。验证真实运行能力后按职责移植，不照搬旧 action engine。
- 当前仓库排期入口已在 internal/module/schedule/handler.go 注册；复用现有页面并验证能力权限与对象授权。

## 6. 执行 PLAN

1. **基线和盘点**：记录分支、dirty 文件、服务 checkout/端口、实际加载资源、页面清单、现有测试结果；追踪各数据源优先级映射和操作链。产出 MATRIX.md，逐页记录发现与验收状态。
2. **公共优先级**：确定 token 和 markup，覆盖 P1–P4/空值/异常值，迁移所有消费页面并清理被替代样式；验证浅色和深色及 CSS 加载顺序。
3. **同类 UI**：根据证据统一对象类型、同义状态展示、行按钮和交互状态；只处理本任务确认的重复和偏差。保留业务状态差异。
4. **导航与排期**：统一标题/ID，补齐正确的对象详情入口；首页接两类排期，验证返回上下文。消除全局 data-demand-id 点击委托对链接行为的误拦截。
5. **阶段办理**：服务端动作合同及授权先行，依次接审批、澄清、提测、测试单、验收/催办、交付、评价。未明契约记录阻塞，独立功能继续；发布保持空操作。
6. **一致性收口**：首页、待办、看板、详情等适用页面消费同一规则；明确历史已办展示历史动作，不能被替换成当前待办动作。操作成功后联动刷新。
7. **全量验收**：完成下列门禁并逐项登记；未通过不得修改为完成。每批更新 PROGRESS.md，包含改动、证据、剩余事项和下一步，方便中断后继续。

## 7. 验收与完成标准

- 每批运行 git diff --check、make check；相关 Go/前端行为测试。记录已有失败为 BLOCKED BY EXISTING BASELINE，不更改门禁或扩大 baseline 放行。

- 授权/阶段测试覆盖业务与独立研发、执行人/参与者/无权限用户、本人/他人验收、待评/已评/多人评价、缺失/多张测试单、状态变化/并发冲突。
- 真实登录浏览器逐类覆盖列表、详情、看板、抽屉/弹窗；浅色/深色、键盘焦点、禁用/加载/错误/空状态和窄屏。确认实际加载资源版本、Console/network 和请求落点。

- 检查页面清单中每项：PASS / PARTIAL / BLOCKED / N/A（给理由），不得只抽样首页就称全站统一。
- 最终交付修改清单、公共规范、逐项验收证据、剩余业务决策和失败/跳过门禁。原审计 EVIDENCE.md 不改写。
