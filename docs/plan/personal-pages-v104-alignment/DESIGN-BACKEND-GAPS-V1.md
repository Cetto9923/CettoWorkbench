## 2. 各页产品验收口径（给实现与联调）

### 首页

- 点焦点：仍在 `/home`，不跳 `/todos`；当前阶段不丢；回到第 1 页。
- 表格条数与「共 N 条」一致；失败显示「暂不可用」，禁止失败装成 0。
- KPI 与当前焦点列表用同一套业务定义（至少在业务需求范围内先对齐）。

**待产品拍板 W1**：焦点/KPI 要不要覆盖研发需求/任务/缺陷；若要，截止日期取哪一列。

### 待办

- 「待接线」Tab：未接通前保持不可点，**禁止显示假 0 冒充已接入**。
- 接通后：与现有需求/任务/Bug 一样有列表、筛选、分页、空态/错误态。
- 审批：只要**当前轮到我**的，不要未来节点、不要纯抄送冒充待审（精确定义见 W2）。

**待产品拍板 W2–W4**：审批边界；问题/风险「我创建 vs 指派给我」；个人事项转派后原创建人算处理还是跟进。

### 已办

- 列表继续只展示「我做过的正式动作」，不是「待办消失」。
- N9：从一行进入动作详情页；对象链接仍可去业务对象。
- 时间/动作/结果组合筛选可测、可说清。

**待产品拍板 W5**：动作详情是否仅本人动作可见（推荐默认：只看自己的）。

### 通知

- 「全部标为已读」仍按**当前筛选条件全部页**（D2 已定），旁白写清楚。
- 「待处理」随对象是否仍可办变化，不锁死在旧通知文案上。

**待产品拍板 W6**：分类以通知自身字段为主，还是继续用事件类型兼容表。

### 关注

- 两 Tab：业务需求 / 项目报告；搜索可用。
- 二级筛选若只对需求生效，UI 上要让人看懂。
