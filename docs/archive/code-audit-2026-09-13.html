P2  /static 未获得 Setup() 注册的全局中间件（gin 注册时序陷阱）

/static 在 New() 中注册，而全局中间件在 Setup() 中通过 Use() 追加，时序倒置：

internal/server/server.go:70 r.Static("/static", "web/static") ← New() 中，先注册 internal/server/server.go:172-184 s.engine.Use(...) ← Setup() 中，后 Use 172 SQLRequestContext 180 Recovery 181 ratelimitpkg.NewGlobalLimiter 182 RequestLogger 183 SecureHeaders 184 MethodOverride

机制已由依赖源码确证（gin v1.12.0，非推测）：

routergroup.go:65-68 func (group *RouterGroup) Use(middleware ...HandlerFunc) IRoutes { group.Handlers = append(group.Handlers, middleware...) // 仅影响此后注册的路由 } routergroup.go:86-91 func (group *RouterGroup) handle(httpMethod, relativePath string, handlers HandlersChain) IRoutes { handlers = group.combineHandlers(handlers) // ← 注册时快照 } routergroup.go:241-248 func (group *RouterGroup) combineHandlers(handlers HandlersChain) HandlersChain { copy(mergedHandlers, group.Handlers) // ← 复制当时的切片 }

后果：/static/*filepath 的 handler 链在注册时已固化为仅 gin 静态处理器，不含 Recovery / GlobalLimiter / RequestLogger / SecureHeaders / MethodOverride。这是隐性陷阱——今后任何加入 Setup() 的中间件都不会保护 New() 中注册的路由。

严重度说明：当前 /static 本就无鉴权（静态资源属预期），实际影响面为「限流/安全响应头/恢复中间件未覆盖」，非授权绕过。但把注册顺序写反属结构性缺陷，建议把 Static 移入 Setup() 的 Use 之后。

七、工具环境坑（复现本报告时必读）

本机 grep 是 toybox 0.8.13，不是 GNU grep 9.0，行为差异会导致「0 处」假阴性：

写法实测结论
grep -c '\bTODO\b' file（BRE）0（实际应 1）\b 失效
grep -cE '\bTODO\b' file（ERE）0（实际应 1）\b 失效
grep -c 'TODO' file（裸串）1 ✓正确
grep -cE 'transition:|zzz' file19 ✓-E 交替可用
grep -c 'a\|b' file（BRE 交替）0（假阴性）BRE \| 失效
本次教训：初次扫描用 grep -rnoE '...\b' 得出「全仓 0 条 TODO」，与随后裸串检索出的 28 个文件命中互相矛盾，才定位到此坑。凡以 grep 的「0 处」作为「不存在」的判定，必须先用确定存在的字符串做对照实验，或改用 ripgrep。
